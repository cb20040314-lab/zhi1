# 智能教育机器人 — 项目整体说明与三方对接指南

> 给采集负责人 & 客户端负责人：先读这份，再看 `docs/data-contract.md` 的字段细节。
> 本文回答三个问题：**整体在做什么 / 你的代码和别人的代码怎么碰 / 一次完整演示是怎么串起来的。**

---

## 1. 项目是什么（一句话）

一个运行在树莓派上的**智能教育机器人**：孩子对着手机说一句话 → 树莓派听懂（ASR）→
生成引导批判思维的回答（LLM）→ 合成语音放给孩子听（TTS）→ 同时通过摄像头人脸特征
实时计算孩子专注度 → 会话结束后生成学习画像，家长在网页上查看报告。

## 2. 整体架构（三角色数据流）

```
┌─────────────────┐   ①音频(webm/opus)    ┌─────────────────────┐  ④回复/音频/报告   ┌─────────────────┐
│  采集负责人      │ ────────────────────▶ │  大数据构建负责人    │ ─────────────────▶ │  客户端负责人    │
│  (手机·Android)  │   ②人脸特征(JSON)     │  (树莓派·FastAPI)   │                     │  (页面·家长端)   │
│                  │ ────────────────────▶ │  ③会话控制/查询     │ ◀───────────────── │                  │
└─────────────────┘                       └─────────────────────┘   ④请求会话/报告   └─────────────────┘
   只产生数据                                   只处理数据               只消费数据
```

- **采集（手机）**：录音、人脸特征采样，只负责"拿到数据并可靠送达树莓派"
- **大数据构建（树莓派）**：存储、AI 调用、清洗分析、画像报告，负责"把数据变成智能"
- **客户端（页面）**：机器人交互页 + 家长网页，只负责"展示和交互"，不做任何算法

> 数据契约已冻结（`docs/data-contract.md` v2.0），三方只通过接口通信，互不越过边界。

## 3. 接口对接全景（谁调用谁）

| 接口 | 实现方 | 调用方 | 作用 | 关键入参 |
|---|---|---|---|---|
| `POST /api/session/start` | 大数据 | **客户端** | 创建会话 | `{}` 或可选 `session_id` |
| `POST /api/turn` | 大数据 | **采集** | 上传音频，得回复 | `session_id` + `audio` 文件 |
| `POST /api/focus` | 大数据 | **采集** | 存一条人脸特征 | `session_id` + 特征 JSON |
| `POST /api/session/end` | 大数据 | **客户端** | 结束会话生成画像 | `session_id` |
| `GET /api/report/{id}` | 大数据 | **客户端** | 查画像+专注度报告 | 路径里的 report_id |
| `GET /api/health` | 大数据 | 三方 | 服务自检 | 无 |
| 采集模块 `Capture.recordAndSend` 等 | 采集 | **客户端** | 录音上传+特征监控 | `sessionId` |

**注意：客户端调"采集模块"（拿媒体数据），也调"大数据接口"（会话/报告）；
采集同学只对接大数据两个上传接口（turn / focus），不碰页面。**

## 5. 对接必看（避免踩坑）

1. **session_id 是唯一纽带**：三方所有请求都带它；客户端创建后传给采集模块，别各存各的。
2. **音频格式**：上传 `webm/opus`（3~8 秒）；过大（>15MB）会被拒绝（错误码 `AUDIO_TOO_LONG`）。
3. **特征字段枚举是写死的**：`expression` ∈ neutral/happy/sad/surprised/unknown；
   `head_direction` ∈ front/left/right/unknown；`eye_state` ∈ open/closed/unknown。
   表情识别不出来就传 `unknown`，**不要猜**。
4. **时间戳用毫秒整数**（`timestamp: 1760000000`），不是秒、不是字符串。
5. **错误响应统一结构**：`{"detail":{"code":"...","message":"..."}}`；前端拿到 code 做提示
   （如 `SESSION_NOT_FOUND`、`AUDIO_REQUIRED`、`AI_TIMEOUT`）。
6. **Mock 模式**：后端默认 `MOCK_AI=1`（预置问答+占位音频），三方可先并行开发；
   联调阶段用同一份 Mock 跑通，再切真实 AI。
7. **画像在 session/end 时生成**：结束前查 report 返回的是实时快照，结束后查返回正式画像。

## 6. 联调时间线（分工文档约定）

| 时间 | 共同任务 |
|---|---|
| 0~2h | 冻结数据契约（已完成 v2.0）|
| 2~10h | 三人对着 Mock 独立开发 |
| 10~20h | 首次横向联调：音频格式、session_id、摄像头元素 |
| 20~30h | 接入真实 AI 回复、画像、专注度报告 |
| 30~40h | 验收补齐：权限拒绝、断网、超时、重试 |
| 40~48h | 冻结功能，连续演练三次 |

## 7. 各自的开工检查

- **采集**：Android Chrome 授权摄像头/麦克风 → 录 5 秒音频 POST /api/turn → 发 20 条特征
  POST /api/focus → 断网重试成功
- **客户端**：POST /api/session/start 拿 session_id → 调采集模块拿回复 → 播 audio_url →
  session/end → 家长页 GET /api/report/{id} 出曲线
- **大数据**：curl 3 段音频 + 20 特征 → 多轮回复 + 画像 + 报告 JSON → 重启后数据可查（已完成）
